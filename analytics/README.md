# Анализ сортировочной линии «Робозон»

Командный хакатонный проект моделирует участок сортировки товаров. Разбор показывает, сколько товаров успевают пройти линию за фиксированное время, как часто возникают ошибки маршрутизации и сколько времени проходит от датчика до решения.

## Результаты за 60 секунд

| Метрика | Значение | Расчёт |
| --- | ---: | --- |
| Поступило / попало в зону датчика / получило решение / дошло до маршрута | 86 / 83 / 83 / 80 | Количество товаров по отметкам этапов |
| Осталось на линии к концу прогона | 6 из 86 | У товара отсутствует конечный маршрут |
| Темп подачи | 5 160 шт/ч | 86 / 60 × 3 600 |
| Темп завершения | 4 800 шт/ч | 80 / 60 × 3 600 |
| Маршруты B / C / D | 31 / 25 / 24 | B — основной сортировщик, C — отвод по габаритам, D — на доупаковку |
| Совпадение маршрута с эталоном | 80 из 80 | Среди завершённых маршрутов с эталонной категорией |
| Критические пропуски на B | 0 из 49 | Среди завершённых маршрутов с эталонной категорией C или D |
| От датчика до готовности решения, p50 / p95 | 78,51 / 115,86 мс | 83 решения, перцентили методом ближайшего ранга |

Разницу между темпами подачи и завершения в этом окне объясняют шесть товаров, которые остались на линии. При скорости 1 м/с и шаге подачи 0,7 м расчётный темп на входе составляет около 5 143 шт/ч. Загрузка шиберов по журналу прогона составила 10,42% и 10,00%, число поздних классификаций — 0. Для оценки предельной производительности нужны прогоны с разным темпом подачи и замеры после заполнения линии.

## Как получены данные

Расчёт основан на одном сохранённом [JSON с журналом кинематической симуляции](https://github.com/IVANCHACHA/hacaton/blob/7a4a452777a2fce8771defba1873af0fe3f91429/sim_output/sim_metrics_run.json). Источник содержит по одной записи на товар. Скрипт строит воронку по `sensor_t`, `decision_ready_t` и `routed_zone` и сравнивает `routed_zone` с эталоном `category_true`. Товары без конечного маршрута остаются в числе поступивших и исключаются из расчёта точности.

Задержку между датчиком и решением задаёт модель. Точность 80 из 80 относится к маршрутизации в одном прогоне с данным набором товаров. Для оценки на реальной линии понадобятся замеры с физического стенда.

## Как воспроизвести

Из корня репозитория, с Python 3 и SQLite 3.25 или новее в составе Python. Скрипт выполняет запросы SQL к журналу в памяти и печатает результаты в JSON.

```bash
curl -fL 'https://raw.githubusercontent.com/IVANCHACHA/hacaton/7a4a452777a2fce8771defba1873af0fe3f91429/sim_output/sim_metrics_run.json' -o sim_metrics_run.json
python3 analytics/analyze.py sim_metrics_run.json --duration-seconds 60
```
