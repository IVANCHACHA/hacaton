# План защиты (≤ 7 минут)

Структура — по рекомендации постановки задачи («Рекомендуемая структура презентации»). Таймкоды —
ориентир, не жёсткий тайминг.

## 1. О команде (30 сек)
*Заполняется командой.*

## 2. Постановка задачи и наш подход (45 сек)
- Участок перед основным сортировщиком: товар → 1 из 3 категорий (B/C/D) → физическая маршрутизация.
- Наш ход: классификация в постановке уже двухступенчатая (габарит → форма) — мы зеркалим это
  **1 сенсорная пара + 2 шибера**, без лишней абстракции.

## 3. Логика классификации товаров (1.5 мин)
- Формулы: габарит [10,10,10]…[450,320,320] мм; K = r_вп/R_оп ≥ 0.8 в любой из 3 ортогональных
  проекций → «круглый».
- Показать таблицу `tools/classify_stl.py` на переданных STL.
- **Ключевой момент для жюри**: сверка с официально подтверждённым числом из Q&A #113
  (Мешок.stl, K=0.817 → D) — наш расчёт даёт 0.816…0.827, тот же результат.
- Разбор пограничных случаев: Цилиндр.stl — НЕ круглый (stadium-профиль, K=0.749) несмотря на
  название; Ручка.stl отбраковывается по габариту (9 мм < 10 мм), а не по форме.

## 4. Схема маршрутизации A/B/C/D (45 сек)
- Показать схему участка (README.md, ASCII-диаграмма) с координатами 0/2.1/2.4/3.4/4.4/5.6 м.
- Приоритет: сначала габарит (шибер 1 → C), потом форма (шибер 2 → D), иначе → B напрямую.

## 5. Исполнительная часть и способ автоматической перекладки (1 мин)
- Механизм: поворотный шибер/лоток, 2 идентичные ячейки.
- Расчёт усилия под 20 кг: ≈230 Н, запас пневмоцилиндра 32мм/6бар — почти ×2.
- Цикл шибера (0.25 с) << окно между товарами (0.7 с) → загрузка ~11% в симуляции, большой запас.
- Связь CV↔исполнение: сигнал `/pak/classification` + независимое отслеживание позиции по ленте;
  бюджет реакции 1.0 с при задержке 40–120 мс — запас ×8.

## 6. Подтверждение работоспособности (1.5 мин) — **живая демонстрация**
- Открыть `sim_web/index.html` — 20–30 секунд живой анимации, обратить внимание на счётчик
  «опасных пропусков в B» = 0.
- Показать цифры прогона: 5148 шт/ч (совпадает с ориентиром постановки ~5000–5150 шт/ч),
  100% точность маршрутизации, 0 опасных пропусков (`sim_output/sim_metrics_run.json`).
- (опционально, если ROS2 поднят) `ros2 topic echo /pak/routing_result`.

## 7. Инструменты и почему именно они (30 сек)
- numpy/scipy (точная геометрия: ConvexHull, LP для вписанной окружности, алгоритм Уэлцла для
  описанной) — без ML и без датасета, которого организаторы не предоставляют (Q&A #46/#72).
- ROS2 (rclpy) — для целевой архитектуры узлов; чистая Python-логика (`core/`) переиспользуется
  и standalone, и в ROS2, и в браузерной демке — один источник истины для всех трёх форматов показа.

## 8. Ограничения и идеи развития (30 сек)
- Нет физического прототипа шибера — только кинематика и расчёт усилия.
- Слипшиеся товары (Q&A #101) — политика описана, не реализована.
- Следующий шаг: тест на независимом наборе организаторов + физический прототип одной ячейки шибера.
